## 1. 一句话诊断

**"呆板"和"不流畅"是两个独立的问题，各有各的根，不能一起修，也不会互相掩盖。**

| 你感觉到的 | 代码里的实际原因 | 备注 |
|---|---|---|
| **字看着一样大、分不出主次（呆板）** | 弹窗里**层级差只有 1.00–1.08×**：13 个弹窗中 6 个的标题与正文比 ≤ 1.077，1 个正好 1.000（完全同大）。同时 **`body` / `html` / `:root` 全仓没有一行 `line-height`**，中文按字体 `normal` 走 ≈1.15–1.25。**层级和呼吸感是同时缺的，缺的还不是同一个东西。** | 排版稿 §2.1 / §2.2 |
| **同一个 13px 在五处在做五件事（角色不存在）** | 弹窗里没有"标题 / 区块标题 / 正文 / 标签 / 元信息"的角色概念，只有一个 13px 到处复用。改一处就牵连五处，所以没人敢改。 | 排版稿 §2.3 |
| **点关闭后第一下点空（不流畅）** | `.overlay` 的 `visibility` 过渡让遮罩在关闭后 **220ms 内仍然拦截点击**（详见 §4.1）。**这是 bug，不是观感问题，没有视觉证据，最难自查。** | 交互稿 §2.8 |
| **弹窗里键盘操作看不到焦点（不流畅）** | 全仓 4 处手写焦点环（`AppSwitch` / `AppTooltip` / `FeedListItem` / `ToastHost`）**一处都不在弹窗里**；`styles.css:690-695` 的 `:focus-visible` 只覆盖 `input/textarea/select`。**弹窗里的按钮，纯键盘用户不知道自己在哪。** | 交互稿 §2.4 |
| **进出场"顿"一下（不流畅）** | **进场有形体（`translateY(8px)`），退场只有淡出，没有形体。** 且时长只有两个值（220ms / 150ms），没有任何一个是按用途定的——反而"出现"慢、"操作"快，节奏是反的。 | 交互稿 §2.1 / §2.2 |
| **合上弹窗背景横跳 4px** | 滚动锁设 `body.overflow: hidden`，滚动条宽 4px。**修法一行**：`html { scrollbar-gutter: stable; }` | 交互稿 §2.5 |

## 2. 四条必须先定的决策（**定完才好施工，否则返工**）

### ① 弹窗要不要跟随"界面字体大小"设置？——**建议本次不做，但必须写明**

应用根 `.app` 有 `zoom: var(--ui-zoom)`（0.9 / 1 / 1.1 / 1.2），而弹窗 `Teleport to="body"`，**落在 zoom 容器之外**（`styles.css:448` + `BaseModal.vue:10`）。

后果：用户把字号调到「大」，主界面放大 10%，**弹窗一点不变**。这不是字号问题，**调 `--fs-*` 修不掉**。

- **做**：一处改动全弹窗生效，但要处理 `AppSelect` 下拉的 `getBoundingClientRect()` 坐标系（下拉也 `Teleport` 到 body，补缩放会让定位算错）。
- **不做**：本轮"整体上移一档"能把观感救回来，但**这个缺陷会留着，必须在文档里写清**，别让人以为修完了。
- 排版稿 §4.4 给了独立提交的方案，**建议排在本轮之后单独做**。

### ② 弹窗放大字号后会被裁掉——**这是硬前置，必须先做**

面板是 `max-height: 86vh` + `overflow: hidden`（`BaseModal.vue:271` / `:285`），而 **6 个弹窗没有内部滚动容器**（`EntityAlertRuleModal` / `FeedAddModal` / `FeedManageModal` / `GlobalModal` / `InsightsModal` / `OnboardingModal`）。

**字一放大，超出的部分直接消失且滚不到，底部按钮跟着一起没。** 每个弹窗约 4 行 CSS（+ `min-height: 0`）。

**这个 bug 在 1440×900 上不暴露，只在 1366×768 或系统缩放 150% 上暴露**——也就是**只在你用户的机器上暴露**。清单 §5.1 有完整做法。

### ③ 中文里字重撑不起层级——**靠字号扛，字重只做补强**

中文字体普遍只有 400 / 700 两档，`500` / `600` 会被浏览器**合成加粗或直接回落 400**。`OnboardingModal:155` 的 `font-weight: 650` 渲染不可控。

所以六个角色**全部绑到既有字号阶梯**，不新增任何数值（排版稿 §3.2）：

| 角色 | token | 值 | 字重 | 行高 |
|---|---|---|---|---|
| 弹窗标题 | `--fs-modal-title` | 18px | 600 | 1.35 |
| 区块标题 | `--fs-modal-section` | 16px | 600 | 1.5 |
| 正文 | `--fs-modal-body` | 14px | 400 | 1.65 |
| 标签 / 列表主字段 | `--fs-modal-label` | 13px | 500 | 1.4 |
| 元信息 | `--fs-modal-meta` | 11px | 400 | 1.5 |
| 大数字 | `--fs-modal-num` | 22px | 700 | 1.1 |

**为什么用角色 token 而不是在 `.base-modal` 里覆盖 `--fs-*`**：`--fs-*` 全仓 **240 处**，弹窗相关 151 处；`--fs-sm` 在弹窗内 55 处且被 `.btn` / `.form-label` / `.save-hint` / `.extract-msg` 共用。粗粒度覆盖会让**按钮和正文一起变**，还会让 `AppSelect` 的触发器与下拉面板字号分叉。清单 §2 R1 有完整推演。

**还有一条硬约束决定了"必须逐文件改"（清单 §2 R10）**：`BaseModal` 是 `<div class="base-modal"><slot /></div>`，插槽内容带的是**宿主组件**的 `data-v`，而 `<style scoped>` 把属性选择器加在规则最后一个复合选择器上。所以：

| 写在 `BaseModal` 里 | 结果 |
|---|---|
| `.base-modal { --fs-modal-title: var(--fs-xl) }` | ✅ **生效**（自定义属性靠 DOM 继承，与属性选择器无关） |
| `.base-modal .m-title { … }` | ❌ **不生效，且不报错** |
| `.base-modal :deep(.m-title) { … }` | ✅ 生效，但穿透**整棵子树**（会顺带打到 `SettingsModal` 的 5 个 tab 和 `MarketPanel`） |

**所以这不是风格偏好，是唯一能生效的写法**：变量定义在外壳一处，消费写给 13 个宿主各自的 scoped 样式。

> **开发必须在 PR 里显式写明选了哪条路**：`一处 + :deep()` 还是 `13 处 + 无 :deep()`。两者影响面对不上，事后无法从代码反推当初的意图。

### ④ 运动尺度定 4 档（挂在 `.overlay` 上，不重定义全局 `--dur` / `--ease`）

| 档 | token | 值 | 用途 |
|---|---|---|---|
| T1 即时 | `--m-tap` | 90ms | 悬停、按下、焦点环、chip 选中 |
| T2 状态 | `--m-state` | 160ms | tab 切换、筛选项、开关、折叠展开 |
| T3 面板进 | `--m-in` | 200ms | 弹窗进场 |
| T4 面板出 | `--m-out` | 120ms | 弹窗退场（**0.6× 于进场**，退出永远比进入快） |

两条曲线：`--m-ease-out: cubic-bezier(0.2, 0.8, 0.2, 1)`（进 / 悬停 / 状态）、`--m-ease-in: cubic-bezier(0.4, 0, 1, 1)`（退场）。**不用弹簧 / overshoot**——这是工具界面，不是玩具。

### 4.1 先看：一个注释写反了的 bug（不依赖任何设计决策）

`BaseModal.vue:247-249` 的注释写着「淡出期间就不会再挡住底层的点击」，**CSS 的实际行为和注释正好相反**。

`visibility` 是离散可过渡属性：渐隐时它在**整个过渡结束时**才跳到 `hidden`。所以关闭动画那 220ms 里，遮罩仍然是 `position: fixed; inset: 0; z-index: 1000` 的**全屏可点击层**——用户点关闭后立刻去点别处，**第一下点空**，而它没有视觉证据，只会被读成「反应慢半拍」。

**修法已写进交互稿 §3.2.2**（基础态 `pointer-events: none`、`.show` 态 `auto`），不再在这里重复开方。只有一点必须记住：

> **缩短过渡时长不算修好。** 220ms → 120ms 只是让点击被吞的时间变短，看起来像好了。**症状减轻 ≠ 病因消除**，验收时最容易被放过。同理，改 CSS 时**要把那句错注释一起改掉**，否则下一个人会把 `pointer-events` 当冗余删掉。

**为什么这类 bug 特别难自查**：被影响的时间窗口**恰好等于 `--dur`**，两者同源。所以谁去调时长，bug 的窗口就跟着一起变——**改时长和 bug 永远同步，永远不会互相暴露**，而且没有任何视觉证据。

**验收就问一句话，别问时长**：

> 关掉弹窗后**立刻**点背景列表里的下一篇文章，**第一下有没有响应**。

只认这一下。`visibility` 那条 120ms 的尾巴**不挡点击**（duration 0s + delay 120ms），真正挡的只有 `pointer-events`——**所以验收要看 `pointer-events` 落没落，不要去看 `visibility` 的时长**。

### 4.2 先看：三处「文档不实」（会让开发走错方向）

1. **`BaseModal.vue` 的注释不可信**（§4.1 就是一例）。
2. **不要用 `display_order` 当可见序号**——正文过滤后会跳号。
3. **`npm run build:frontend` 在本环境跑不完，根因未查明**（曾有"undici WASM OOM"的说法，已核实 `package.json` / `package-lock.json` 里 undici 计数均为 **0**，该归因不成立）。**它现在什么都不证明**：失败了不代表代码有问题，通过了也不代表没问题。验收只用 `npm run typecheck`（基线 0 错误）+ 真机 `npm run dev` 逐项目视。

## 5. 已知缺陷：本次不修，但必须知道

1. **弹窗不随界面字号缩放**（决策①）——留着，单独排期。
2. **`--fs-md` 与 `--fs-base` 同为 14px**，两个 token 一个值。
3. **13 个弹窗的标题规格有 4 套并存，3 个弹窗没有标题**。
4. **整个弹窗体系只有 1 个 `@keyframes`**（`BaseModal` 的进场）。
5. **22 个弹窗系文件里 `:first-child` / `:nth-child` / `:last-child` / `:nth-of-type` 共 0 处**——所以在弹窗里插新节点**不会**踩结构伪类。这条是"可以放心动"的证据，不是缺陷。
