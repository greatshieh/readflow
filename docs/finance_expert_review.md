# ReadFlow 证券/金融投资行业专家功能评审

> 评审视角：买方研究员 / 卖方分析师 / 个人投资者中的"研究情报"使用者
> 评审基线：2026-10-11 已落地代码（M1–M4 主线 + P0-D 事件预警 + P1-F 实体告警 + P1-E 播客视频源 + 事件类型预设/自定义体系 + HTML 研究报告）
> 评审方法：代码实证（grep 确认数据源与事件类型覆盖范围）+ 行业需求映射，非凭印象

---

## 一、产品真实定位（先定性，再评功能）

经代码实证，ReadFlow 的数据摄入**完全依赖 RSS**（全仓无行情/报价/持仓/自选股/期货代码类实现），AI 抽取层仅接收文章标题+正文+链接。

**结论性定位**：ReadFlow 是一个**本地优先的"金融新闻/披露情报聚合 + AI 综述"工具**，是 Wind / 同花顺 / Bloomberg 之外的**AI 情报层**，而**不是**行情终端、研究终端或交易系统。对证券从业者的价值在于"跟踪实体/主题/事件的舆情与披露动态并自动生成研究脉络"，而非"看盘/估值/下单"。

这一边界决定了下面所有"优势"与"缺口"的判断标准。

---

## 二、已具备的、对金融从业者真正有用的能力（优势）

1. **实体级追踪 + 情感评分**（`entity_score`，命中×20 封顶 100）
   - 可按公司、行业、宏观主题建实体，跨源聚合其舆情温度。对"盯一家公司与它的上下游/竞品/监管"的买方研究员高度契合。
2. **finance 事件类型 + 情感标签**
   - 财报 / 评级 / IPO / 分红 四类，配合强情感（利好/利空/中性）标注，事件流可读性强。
3. **双层事件预警**
   - P0-D 强情感事件主动推送 + P1-F 实体级规则（类型/情感/关键词组合）。研究员可把"某持仓股出现利空"设成规则，免去人工刷新闻。
4. **关系图（GraphView）**
   - 实体共现网络，适合做主题映射（如"某政策→哪些公司受益/受损"的链路梳理）。
5. **AI 研究报告（HTML + MD 双写，Obsidian 导出）**
   - 聚合情感、时间线、按类型双视图 + AI 叙述。对"把一周舆情整理成研究笔记"有直接提效；来源链接全程可追溯（金融场景防幻觉的关键）。
6. **本地优先 / 隐私**
   - 敏感研究（自选标的、预设规则、未公开观点）不出本机，对合规与个人研究保密是加分项。
7. **尊重 A 股惯例**：时间线圆点红=利多/绿=利空，与境内用户直觉一致（已在视觉重设计中落实）。

## 三、对证券/投资从业者的关键缺口（按严重程度）

### P0 — 决定"能否进工作流"的硬缺口
1. **无实时行情 / 基本面数据**：纯 RSS 新闻驱动，没有报价、指数、板块涨跌、财务三表、估值、一致预期。研究员无法把"新闻"与"价格/估值"对齐，情报无法落地为判断。
2. **finance 事件类型过窄（仅 4 类）**：缺失证券分析高频类型——
   - 业绩预告 / 业绩修正 / 预期差（earnings surprise）
   - 回购 / 增持 / 减持 / 股权激励
   - 可转债 / 配股 / 定增 / 解禁
   - 违规处罚 / 立案 / 退市风险 / 停牌
   - 融资融券 / 北向资金 / 大宗交易 / 龙虎榜
   - 并购细节（当前 `ma` 在 business 域，finance 域未单列）
3. **无财报日历 / 业绩预告集成**：研究员最刚需的"未来事件"视图缺失，只能被动等 RSS 出文。

### P1 — 影响"是否愿意日常用"的体验缺口
4. **情感标签二元化（利好/利空/中性）过于简化**：金融事件常是非对称的（"营收略低于预期但指引上调"），且需要幅度/概率维度；当前无法表达强度梯度，预警易误报/漏报。
5. **无自选股 / 组合联动**：实体追踪与"我的持仓"脱节，无法做持仓相关度加权或组合层预警。
6. **预警仅情感/规则触发，无价格触发**：无法"跌破某价提醒"，对交易型用户价值打折。
7. **A 股专属高质量源缺失**：巨潮/上交所/深交所公告、卖方研报摘要、龙虎榜、北向等 RSS 难稳定获取，且需手动维护源（无 OPML 批量/无 RSSHub 内置）。
8. **无客户报告导出（PDF / Excel）**：HTML 报告适合自读，但不便于给客户/团队分发。

### P2 — 进阶研究能力缺口
9. **无信号回测 / 验证**：实体情感能否预测涨跌、预警命中率如何，完全没有实证，研究员难以建立信任。
10. **无多源去重与可信度加权**：同一事件多源报道未聚合去重，付费终端源与自媒体源未区分权重。
11. **跨设备/协作缺失**（本地优先的双刃剑）：研究无法在多端同步、无法团队共享标注。

## 四、风控与合规视角（金融场景特有）

- **优点**：报告页脚已有 AI 免责声明；来源链接全程可追溯，降低幻觉风险。
- **风险点**：
  - AI 叙述 + 二元情感可能在金融场景产生**误导性简化结论**，当前缺少"需人工复核"的强提示与置信度展示。
  - 本地优先使数据**无审计留痕**，若用于合规留存（如研究合规）反而不满足留痕要求——需明确告知用户"本工具不构成投资建议、不替代合规存档"。

## 五、给产品方的优先级建议（让 ReadFlow 真正服务金融用户）

| 优先级 | 建议 | 说明 |
|---|---|---|
| **P0** | 接入行情/基本面数据 + 财报日历 | 用可联网金融数据能力补"价格/估值/未来事件"维度，情报才能落地 |
| **P0** | 扩展 finance 事件类型至 12+ 类（见第三节） | 当前 4 类不足以覆盖研究日常 |
| **P1** | 自选股/组合联动 + 价格触发预警 | 把"舆情"与"我的持仓/价格"打通 |
| **P1** | 卖方研报源 + PDF/Excel 导出 | 贴近研究员真实产出物 |
| **P1** | 情感加幅度/概率维度 | 缓解二元误报 |
| **P2** | 信号回测 + 多源可信度加权 | 建立金融用户对 AI 信号的信任 |
| **P2** | A 股专属源模板（巨潮/北向/龙虎榜） | 境内从业者刚需 |

## 六、总体结论

ReadFlow 在"**金融舆情与披露事件的 AI 聚合、追踪、综述**"这一细分场景上，已经完成了一个**可用且隐私友好**的 MVP：实体追踪、事件预警、关系图、AI 报告四件套对"做主题研究、盯公司与行业动态"的买方/研究员有实打实的提效。

但必须清醒：**它当前是"情报层"而非"分析终端"**。缺少行情/基本面/财报日历/组合联动，使其无法进入证券从业者的核心决策工作流；finance 事件类型与二元情感的简化，也限制了它在严肃投研中的可用性。

**一句话评价**：作为 Wind/Bloomberg 之外的"AI 读新闻写纪要"副驾很有价值；若想成为金融用户每日必开的主工具，P0 的数据与事件类型补全是绕不开的门槛。

> 注：本报告基于代码实证与行业需求映射，未对 GUI 做真机目视复验（沙箱限制）。涉及行情/基本面/研报的具体接入方案，需结合可联网金融数据源另行评估。
